## 何謂身份驗證

三種主要的身份驗證：

- 知識因子 (Knowledged Factors)：你知道什麼？ 例如：密碼、PIN 碼等
- 持有因子 (Procession Factors)：你擁有什麼？ 例如：手機、OTP Token 等
- 生物特徵因子/固有因子 (Inherence Factors)：你是什麼？ 例如：指紋、虹膜等

### 驗證 vs. 授權

「驗證」與「授權」的不同在於，前者是一個確認使用者身份是否如該使用者所稱，例如輸入一段電子信箱跟密碼，假設密碼或者電子信箱不符，
有可能是忘記信箱或密碼，或是該名使用者在嘗試侵入他人信箱；後者則是需要確認使用者是否可以被允許做某些行為，例如：刪除一段紀錄，新增一筆記錄等。

### 基於密碼登入的資安漏洞

#### 暴力攻擊 (Brute-forced Attack)

暴力攻擊 (Brute-forced Attack) 指得是透過「反覆嘗試」猜測使用者憑證。通常運用使用者名稱和密碼字典來進行自動化攻擊，如果使用專門工具便能以高速進行大量的登入嘗試。

雖然這種攻擊是透過隨機使用者名稱和密碼字典來嘗試破解，但攻擊者本身可用基本邏輯搭配公開資訊來微調，以利做出更針對性地猜測。

##### 暴力破解使用者名稱

企業在建立員工電子信箱時，幾乎都會依循相同的格式，例如名字 + `@companyname.com`，而像是擁有最高權限的使用者，名稱通常是 `admin` 或 `administrator`，這種情況下就很容易被攻擊者猜測。
若要避免，要密切檢查網站是否有公開洩漏潛在的使用者名稱，或者在未登入的情況下也可存取使用者個人資料等；另外也應該檢查 HTTP 回應看是否有洩漏電子信箱地址。

##### 暴力破解密碼

密碼的破解取決於它的強度，目前許多網站都採取差不多的密碼建立策略，必須強制讓使用者的密碼至少是：

- 最少字元數
- 大小寫字母混合
- 至少有一個特殊符號

但依照使用者的行為慣性，通常不會選擇「記不住」的密碼，而可能會將某種已經記住的習慣 (比如生日，電話等) 無意識或有意識地納入建立密碼的原則。雖然有些網站或系統會要求更改密碼，
不過依舊可能只會針對原密碼小範圍的修正，這也讓攻擊者更可以有邏輯地去推敲出可能的密碼組合。

##### 使用者名稱枚舉 (Username enumeration)

你可能有過這種經驗，例如登入時可能輸入錯誤信箱或是密碼，但是網站顯示的貼心錯誤寫著「帳號不存在」或是「密碼錯誤」，對於使用者來說可以更快識別問題，相對地對攻擊者來說也是。
另外在帳號存在與不存在之間的時間差以及 HTTP 狀態碼跟回應長度，這些都可以作為攻擊者確認使用者是否存在於系統中的細節；以下是幾種防範的方式：

1. HTTP 狀態碼跟回應長度：

網站不論什麼情況，都回應相同的狀態碼。但如果業務需求，必須顯示差異，那就必須引入多層次的防範。
上述所說的使用者登入或註冊的情境中，為了良好的使用者體驗，通常是必須告知使用者註冊或登入狀態，若成功的話 HTTP 返回 `201 Created`，反之，若失敗則是 `400 Bad Request`，已存在的話則會顯示 `409 Conflict`。

社群媒體也是其中一個例外，因為這些平台的初衷就是公開個人資訊，回應狀態自然有所差異，例如 `200 OK` 和 `400 Not Found`，其他就不一一贅述，只要知道因應企業商業邏輯，
雖然「回應相同的狀態碼」是最佳實踐，但會隨業務需求退而求其次，但這不意味著要犧牲資安，而是需要透過類似「人機驗證」、「雙層驗證」、「多因子驗證」或者「速率限制」等補償性的防範手段來避免使用者枚舉。
