## 第一部分：Docker 基本認識

加入 PyLadies 參與他們的官網專案的時候就接觸過 Docker，但我一直沒有真正地深入去研究，對「當時」的我來說，Docker 是一個可以「統一」環境跟套件的虛擬空間 😅，雖然這樣講好像也沒有錯，不過更具體來說，Dokcer 是一個容器化（containerization）平台。

**容器化（containerization）** 是指隔離軟體執行環境，乍看之下概念很像虛擬機器或者 Python 的虛擬環境，只是差別在於隔離的層次不同。
把 Docker 想成是大樓裡面的一間套房，共用大樓裡的所有設施，每一個房間彼此獨立；虛擬機器就比較像是透天厝，你要自己先蓋好地基，牽好水電等基礎設施。那 Python 的虛擬環境呢？

Python 的虛擬環境只隔離了 Python 套件，我們可以在不同的專案，透過各自建立的虛擬環境安裝所需版本的套件，也可在同一個專案建立虛擬環境來安裝不同版本的套件，只是要啟用的話就要特別注意，因為一個 shell 只能啟用一個，在路徑上要註明清楚讓 Python 指令知道要指向哪個資料夾。

### 核心元素

#### 映像檔 (Image)

映像檔是一個唯讀的模板，包含著執行某個轉體所需的一切，例如作業系統、程式語言、相關套件以及指令等，把這個想像成一份食譜。
做成這份食譜的方式有兩種：

- 從 Docker Hub 抓現成的
- 建立 `Dockerfile`

#### 容器 Container

當 Image 執行，會建立一個實例，也就是容器，這個容器是一個與外界隔離的空間，所有 Image 需要執行的都將在這個獨立的空間進行。當執行 `docker run <image>` 就是用這個映像檔開一個新的容器。

同一個 image 是可以同時有多個容器，但每個都是獨立的；容器是**無狀態的（stateless）**，也就是說在這個容器內做的任何事情，一但被刪除（rm），就全部消失；但如果只是停止，那就還會存在。

#### 資料卷 (Volume)

由於容器是無狀態的，一刪除就沒有任何資料，資料卷則是掛載在容器某個路徑的持久化儲存空間。如果容器被刪除，只要重新掛同一個資料卷，那麼就可以保有之前的資料。常見有兩種：

- Named Volume：由 Docker 管理
- Bind mount：直接指定主機資料夾
- 指令：`docker volumn ls` 可用來列出所有資料卷；`docker volume` 刪除資料卷
